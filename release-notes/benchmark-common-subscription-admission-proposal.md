It is a pre-launch eligibility check, not a new Core authority, scheduler, auth store, cache or provider. Its retained scope remains private and nonserializable.

4. Bind the accepted route result and successful inventory to that immutable scope in a private, single-use local object. 5. After any expected prefetch/activation validation and immediately before start, recheck the bound code identity, attempt fixture and exact cloned scope. Run the existing single client attempt and existing fixed answer/edit oracles. Preserve failure and refuse another submission on denial, cancellation, inventory/cleanup error or scope change. Report native retries/worker totals as unknown when not authoritatively observed; configured feature denials do not measure total native activity.

The canonical provider/base-URL overrides must be identical for probe, inventory and exec. API-key, logged-out, custom/unknown route, conflicting/unknown requirements, malformed/duplicate/oversized responses or nonzero/ambiguous lifecycle results stop before the model. Neither a declared requested model nor this metadata qualification proves model availability. Required unsupported policy must stop rather than be bypassed.

The scope object freezes command inputs, not external state. User/system/project/cloud requirements, auth and policy can change between the four responses, inventory and exec. All later invocations reload ordinary effective configuration. Admission is a bounded pre-prompt observation, not pre-network isolation or atomic later-exec authorization. The official client may perform its normal OAuth/cache updates. Raw RPC/config/account values remain bounded host RAM only, never traced, copied, hashed or sent to a model.
