# IVOAI v0.9.0

This stable release makes OpenCode the managed interactive frontend for IVOAI AUTO.
IVOAI remains the authoritative control plane and routes execution through the
official Codex or Claude Code CLI, preserving each client's existing subscription
login without copying credentials into OpenCode.

## OpenCode-first AUTO

- `ivoai auto` and `ivoai opencode` open the pinned OpenCode TUI attached to a
  private IVOAI-managed backend on a random `127.0.0.1` port.
- IVOAI owns executor eligibility, quota routing, policy, Skill Gate, knowledge,
  WorkingContext, compression, lifecycle, and the single-writer boundary.
- The managed OpenCode provider is a local UI transport. Codex and Claude Code remain
  the actual executor contracts and use their official native authentication.
- The standalone upstream OpenCode provider path remains available explicitly with
  `ivoai session start --executor opencode --mode direct`.

## Authentication and sessions

- Codex credentials, Claude credentials, cookies, and refresh tokens are never read,
  copied, converted, or inserted into OpenCode.
- Managed configuration disables project overrides, sharing, provider drift, and
  OpenCode auto-update without modifying the user's normal OpenCode installation or
  configuration.
- OpenCode conversation IDs map to separate Codex and Claude conversation IDs using
  bounded, non-sensitive metadata. Restart and executor switching resume the matching
  conversation only when working directory and knowledge scope match.
- Cancellation terminates the selected official executor process group. Quota
  failover stays in the same OpenCode interface and refuses a second executor launch
  after partial output.

## IVOAI terminal integration

- The managed frontend uses supported OpenCode plugin, theme, route, command, and slot
  APIs; no OpenCode fork is carried.
- The IVOAI home lettering, compact knowledge summary, sidebar, and `/ivoai` panel
  expose executor auth/quota state, compression, Memory, Context, skills, and bounded
  multi-server health.
- Symbols are paired with words, untrusted labels are sanitized and bounded, and
  missing evidence is reported as unavailable or stale instead of invented.
- Sharing and auto-update are disabled only in IVOAI managed mode. Direct `opencode`
  behavior is unchanged.

## Multi-server knowledge

All enabled sources still participate in default bounded read federation. Repeated
`--knowledge-source` flags restrict the session to an exact subset. The TUI shows
configured, connected, selected, excluded, healthy, down, automatic, restricted, and
degraded state from the same ServerPool/Knowledge Router snapshot used for routing.

Per-server credentials remain isolated. Read degradation never enables cross-purpose
fallback, and writes are never broadcast: ambiguous new writes continue to fail
closed until one deterministic destination is selected.

## Tools, policy, and fidelity

The official executor CLI remains the owner of tool execution and permission checks.
The OpenCode frontend receives sanitized lifecycle markers rather than raw tool
arguments or results; repository diffs remain available from the managed OpenCode
session. Authoritative Memory/Context keeps the provider-neutral exact-required
bypass, and Caveman, Headroom, and Direct remain mutually exclusive.

## Documentation accessibility

The self-hosted Docusaurus portal now uses centralized semantic tokens, independently
authored light/dark palettes, visible focus, reduced-motion support, responsive table
and code overflow, and higher-contrast syntax/admonition/search states. Playwright +
axe covers representative routes at 375, 768, 1024, and 1440 px in both themes, plus
keyboard skip navigation and 200% zoom. The production docs service remains a static
embedded build served by the unprivileged IVOAI systemd service on `0.0.0.0:7780`.
The OpenCode backend is never exposed on that listener.

## Install and update

```sh
curl -fsSL https://raw.githubusercontent.com/ivo-lopes/ivoai/v0.9.0/install.sh | sh
ivoai update --dry-run
ivoai update
```

Existing configuration, native executor authentication, multi-server profiles,
per-server secrets, Memory/Context state, skills, and user-owned OpenCode files are
preserved. Managed OpenCode assets are version matched and rollbackable. Use
`ivoai update --rollback` to restore the previous verified binary and compatible
IVOAI-owned mutable state.

## Security and provenance

OpenCode remains pinned to official stable release 1.18.25 and verified by SHA-256.
The release gate downloads that exact artifact and exercises both the real HTTP
provider path and the real attach TUI. The local backend and bridge use independent
ephemeral credentials, loopback-only listeners, private directories, bounded input
and output, process-group cleanup, and an allowlisted environment.

## Known limitations and deferred roadmap

- OpenCode is the managed frontend, not an AUTO worker. Codex and Claude Code remain
  the subscription-backed executor/worker contracts.
- Provider-specific nested tool animation from a hidden executor CLI is represented
  by sanitized lifecycle markers rather than recreated as a second TUI.
- Headroom remains available as a compatibility and rollback provider.
- Ruflo remains the bounded lifecycle implementation for current orchestrated modes.
- OpenViking, NativeOrchestrator v2, complete Conversation Continuity, the complete
  monitor TUI, and other final-vNext work remain planned and are not enabled here.
