# IVOAI v0.14.0

Incremental release candidate based on main `2bf9f943`, following v0.13.0.
Publication requires the final source CI and draft-first Release pipeline to
pass. This document does not establish publication or production deployment.

## Delivered scope

- **Local administration (IVOAI-189):** explicitly started, authenticated,
  read-only console using the same App, session store and scoped OAuth mechanism.
  PKCE/state/CSRF, private instance-bound access, revocation, bounded DTOs and audit
  preserve the backend authority. The inventory has 118 TUI actions: six partial
  read projections, 112 pending and none complete. No conversational frontend.
  The admin HTTP listener exposes only the browser authorization form from the
  shared OAuth server; unused external registration/token/discovery routes are
  closed while the Web MCP OAuth contracts remain available on their own service.
- **Native worker controls (IVOAI-192/193):** managed Codex forces
  `agents.enabled=false` and `features.multi_agent_v2=false`, rejects `--enable`
  overrides and preserves configuration precedence. A pinned official 0.162.1
  proof executed native workers in four positive controls and refused them in
  two managed cases. This is not universal certification of future clients.
- **Compression policy (IVOAI-201/46):** Headroom's managed wrapper is refused
  before startup because the pinned wrapper registers configuration in client
  homes. Installed components/preferences remain intact; Direct is the fallback
  and Caveman remains the default. Unknown fidelity/content cannot acquire lossy
  eligibility. Canary quality and applied-transform availability are separate.
- **Reported usage (IVOAI-138):** Core traces retain strict Codex exec input,
  output and optional cached-input reports for one invocation. Cache is included
  in input. Missing/conflicting measurements stay unknown; no price, quota or
  session aggregate is fabricated.
- **Optional evidence/code pilots (IVOAI-199/200/190):** bounded local VERSION
  turns remain disabled by default; RTK-OSS snapshot views are programmatic and
  retain exact artifacts; Codebase Memory has an injected, disabled-by-default
  symbol/direct-caller reader for a previously authorized index. No automatic
  install or App routing is added for RTK/Codebase. Graft/direct remain available.
  The diagnostic Codex evidence runner requires a synthetic loopback provider
  and still refuses production admission.

## Validation and economic limits

PRs [41](https://github.com/ivo-lopes/ivoai/pull/41),
[42](https://github.com/ivo-lopes/ivoai/pull/42) and
[43](https://github.com/ivo-lopes/ivoai/pull/43) each passed 15/15 checks at their
reviewed heads. Browser CI requires the real local App/OAuth/Store to exit
successfully in independent logout/revocation flows; fixture skips cannot count
as success. Seeded session/usage data is not a live provider execution.

The new pinned Caveman MCP canary passed 22 scenarios: 17 calls, one applied
transform, 16 passthroughs and five bypasses, with no degradation or mismatches.
Its context-byte ratio includes the projection budget, summaries and references;
it is not a session compression ratio. This was one run, not a Direct/ABBA study.

The expanded live comparison preserves 42 new official Codex attempts, all
correct, and all 72 earlier attempts. In the new seven-case subset, input rose
533847→549059 (+2.85%) and elapsed time fell 136153→134193ms (−1.44%). The
10% input/5% time targets failed. **Subset: FAIL; global 16-case gate: INCOMPLETE.**
Those measured binaries predate this release candidate; no causal benefit from
the later changes is claimed. Failures, adverse results and unavailable cases
remain recorded, rather than rescored or counted as successful execution.

## Compatibility and remaining work

No personal client configuration, credential, executable or history is removed.
Linux AMD64v1 and ARM64 remain build targets; distribution runtime gates belong
to the exact tagged artifacts. New read-only admin access is local-owner only,
without remote or organization RBAC. Reverting the code restores the prior
behavior, including the refused unsafe optional Headroom path; rollback does not
reverse existing unrelated data migrations.

General adaptive execution without a DAG, removal of operational OpenCode
dependencies, authenticated Claude equivalence, Antigravity runtime integration,
institutional/tool evidence adapters and complete web administration remain
pending. Context ingestion is still `CONTEXT_SYNC=BLOCKED` under IVOAI-175.
Writing Memory does not synchronize Context. No new compression default,
OpenViking cutover, complete roadmap delivery or global economic success is claimed.

## Português

Candidata a entrega incremental: console administrativo local autenticado e
somente leitura, controles de workers nativos do Codex fixado, proteção contra
o wrapper Headroom que modifica configurações, métricas de uma execução e pilotos
opcionais de evidências/inteligência de código. A publicação depende dos gates
do commit/tag; não há implantação em produção nem paridade administrativa completa.

A nova comparação real preservou 42 tentativas corretas, além das 72 anteriores:
entrada +2,85% e tempo −1,44%. As metas de 10%/5% foram reprovadas; a matriz global
continua incompleta. O canary Caveman prova qualidade e uma transformação aplicada,
sem comprovar economia da sessão. Falhas e limitações permanecem nos relatórios.

OpenCode ainda possui dependências operacionais. A execução adaptativa geral,
equivalência autenticada Claude, Antigravity e ingestão Context não são entregues
por esta candidata. O console cobre parcialmente seis das 118 ações inventariadas.
Configurações, credenciais e históricos pessoais são preservados. Consulte o
[guia do console](../docs/admin-console.md) e as evidências antes de promover.
O listener administrativo limita as rotas OAuth ao formulário de autorização
do navegador; o serviço OAuth do Web MCP mantém seu contrato completo.
