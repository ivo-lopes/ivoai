# IVOAI v0.16.0 — natural managed Codex turns

IVOAI Core can admit natural requests, complete eligible simple turns without a
DAG, preserve an owned native conversation across consecutive turns, and escalate
the same Primary invocation through the existing planning, approval, scheduler,
worker and validation contracts.

## Changes since v0.15.0

- Managed admission uses bounded text-integrity checks directly. Formal acceptance
  criteria are not required. Empty/oversized/invalid UTF-8 or unsafe-control input
  still fails before executor preparation. Invalid-input diagnostics now use
  `PROMPT_INPUT_INVALID`; diagnostic Result fields and the legacy completion
  transport remain compatible. Consumers matching `PROMPT_INSUFFICIENT` should
  accept both labels during rollout and use the new label after upgrading.
- Fresh receipts bind consecutive adaptive turns to the same frontend, owned
  native thread/account reference, successful prior attempts, scope and unchanged
  host configuration/runtime. Failed, foreign, stale or replayed turns cannot
  acquire authority through conversation history.
- Native frontend shutdown uses stdin EOF. Linux cleanup reserves the leader PID
  until its final process-group signal and retires cancellation before reap.
  Forced timeout/cancellation is reported separately from a normal exit.
- Exact code lookup instructions select the existing Code Intelligence contract.
  Proven absence of optional Graft supports builtin Direct; an invalid or claimed
  managed installation still fails closed. Missing graph evidence is not
  fabricated from a text match.
- A reproduced stable-upgrade failure is fixed: identical managed Graft bytes
  republished at another official IVOAI release URL reuse the original verified
  object. The installer, runtime preflight and Doctor share the same narrow
  identity check; revision, digest, architecture, publisher, trust and every
  other metadata field must still match. Original provenance stays immutable
  and compatible with rollback to the published v0.15.0 Core.
- Existing benchmark admission and offline activation controls are included;
  they are prerequisites and regression checks, not economic certification.
  Connector restart diagnostics no longer imply successful Context recovery.
- `follow-redirects` 1.16.2 and `joi` 18.3.1 remove the high documentation advisories;
  the separate runtime lock also pins `follow-redirects` 1.16.2. Runtime profile
  identity follows its package/lock digest, retaining earlier profiles for rollback.
  No audit threshold or exception was weakened.

## Controlled activation

```sh
IVOAI_EXPERIMENTAL_ADAPTIVE_PRIMARY=1 ivoai codex
```

The adaptive flag stays **OFF by default**. It requires the exact reviewed managed
**Codex 0.162.1 Linux amd64 executable/Code Mode companion pair** documented in the
[pilot provenance](https://github.com/ivo-lopes/ivoai/blob/main/release-notes/experimental-adaptive-primary.md).
The certified scope is a new eligible managed conversation in the same owner
process, with consecutive successful read-only turns. A matching version banner
alone does not admit another binary. Cross-process resume, earlier conversations,
prior DAG/checkpoint histories, other client versions/platforms and dynamic
primary MCP catalog expansion are not newly certified. Their existing guarded
contracts remain in force.

The read-only Primary gains no write or privileged execution permission by
answering directly. Mutations still require the existing Core plan, exact task
grants, approvals, isolated workers and validation. Subscription credentials
remain owned by official clients; no token extraction or paid API fallback is
introduced. Caveman remains the default compression provider, Headroom optional
and Direct the existing fallback.

## Evidence and quality

The [functional report](https://github.com/ivo-lopes/ivoai/blob/main/release-notes/adaptive-primary-natural-turns.md)
preserves 16 execution epochs, including failures. Real official subscription
inference validated two natural turns through the public production `ivoai codex`
command (38.151 s), a completed Direct code lookup, an approved one-worker fix,
an approved two-worker change, cancellation and denied-read cancellation. Fixed
executable tests failed before the controlled changes and passed afterward; only
the approved files changed. Native TUI/backend and the public wrapper exited
normally, preserving one conversation and finishing the Core session.

An additional private overlay recorded real inference after owner revocation of
an active Core receipt. The CLI completed normally; Core withheld its final
answer, returned `ADAPTIVE_PRIMARY_DENIED`, retained NoReplay/NoAutomaticFailover
and returned duplicate HTTP 409, with no second attempt, DAG, worker or file change.
This revoked Core authority, not any subscription credential. Its [receipt and source hash](https://github.com/ivo-lopes/ivoai/blob/main/release-notes/evidence/v0.16.0-preparation/core-receipt-revocation.json) are retained; the test source is included in this release.

The inherited functional source passed 59 Go packages under race detection, vet,
105 Python checks, 9 native AUTO fixtures and the pinned native frontend protocol
checks. Both PR #69 and its actual main merge `67cee56c` passed all 16 CI jobs with
zero skipped jobs. Real inference is separate from synthetic-provider protocol
checks and opt-in skips are not counted as successful inference.

Publication requires the tagged source's Release workflow: tests/race/vet,
protected-evidence rollback, security audits, installation/upgrade gates, native
ARM64 and amd64 without AVX, exact version/clean-source Core builds, and verified
component archives. The draft asset set, local bytes and downloaded bytes must
agree before publication. Core distribution support for ARM64 does not imply
adaptive ARM64 certification.

## Economics, migration and rollback

**Global economic gate: INCOMPLETE.** CLI-reported primary input/output/cache usage
is recorded; worker usage and billing/aggregate session savings are not established.
There is no comparable Gateway OFF/ON cohort or claimed 10% token/5% time gain.
Unfavorable historical observations remain unchanged. A smaller tool result or an
observed provider cache count is not a measured whole-session saving.

The versioned release gates test the previous stable Core against this candidate
in an isolated installation, including preserved managed configuration, synthetic
credential markers, idempotence and rollback. This is separate from the retained
v0.5.0 bridge tests and does not touch real user credentials or production data.
The preliminary amd64 run passed 11 executable checks in 383.241 s. The tagged
workflow repeats the gate against its actual archives on both architectures.
[Preparation evidence](https://github.com/ivo-lopes/ivoai/blob/main/release-notes/evidence/v0.16.0-preparation/validation.json)
preserves all earlier failures, the interrupted run, and a loaded local race
timeout whose unchanged test and complete App suite passed in isolation. No
failed run was converted into a success. Official provider diagnostics remain
blocked before TLS in this isolated upgrade test; catalog/quota availability and
inference are not certified by it. The reviewed baseline/candidate pair must be
advanced explicitly for the next stable release.

Unset experimental flags for future launches to roll back behavior. Finish or
cancel admitted work before a downgrade. Use a verified matching Core/component
set and the documented updater rollback; retain receipts, claims, attempts,
mappings, checkpoints, protected artifacts and previous runtime profiles. Never
delete histories to force replay or modify personal native-client configuration.

This release does not claim global OpenCode removal, Claude/Antigravity TUI parity,
a complete administrative panel, or completion of the wider backend-first roadmap.
PR #54 remains excluded while its inconclusive failures are unresolved. Evidence
from the integrated functional increment has been registered in the existing Plane
tasks IVOAI-191/192/193/197/198/199; their broader acceptance criteria remain open.
Context returned no documents for the release research query. Document ingestion
and Context synchronization remain dependent on IVOAI-175; writing a memory page
does not synchronize Context.
