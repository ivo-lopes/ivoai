# IVOAI v0.8.0

This stable release closes a focused set of operational gaps in the current IVOAI
snapshot. It does not complete or enable the deferred vNext roadmap.

## Highlights

- Unfiltered client sessions now use every enabled, connected `ivoai-server` for
  bounded read federation. `--knowledge-source` is an exact restrictive filter.
- Debian 12 server setup can provision a missing Docker Engine from Docker's
  official signed APT repository and reports LXC host-policy blockers explicitly.
- The official documentation is now a searchable, versioned Docusaurus portal
  embedded in the IVOAI binary and served by a hardened systemd service.
- The unified remote `/mcp` endpoint has explicit Streamable HTTP content
  negotiation and current setup guides for ChatGPT Web and Claude Web.

## Multi-server knowledge

All enabled sources participate automatically in read-only federation. Results are
merged deterministically and retain source ID, alias/purpose, and redundancy
provenance. A failing automatic source produces a visible partial/degraded result
without blocking healthy sources. An explicitly requested unavailable source still
fails closed.

Automatic read federation never means write replication. New Memory writes require
one deterministic destination; ambiguity fails before any upstream call. Per-server
credentials remain isolated and are never exposed to executors.

## Debian 12 and LXC server bootstrap

`ivoai setup --mode server` reports OS, architecture, container/LXC, Docker CLI,
Engine/daemon, Compose v2, systemd, privileges, and existing setup state before
mutation. Debian installation uses Docker's signed official repository, reviewed key
fingerprint, and exact package candidates. Missing LXC nesting, keyctl, cgroup, or
device permissions are identified as host-side requirements.

Incomplete setup is reported as `SERVER_SETUP=INCOMPLETE` with the prerequisite root
cause instead of treating generated `.env` files as the primary failure.

## Documentation service

Server setup enables `ivoai-docs.service`, serving the prebuilt Docusaurus site on
`0.0.0.0:7780` by default. The service is unprivileged, starts at boot, restarts on
failure, logs to journald, and uses no development server or writable Node runtime.
Use an external Nginx Proxy Manager for public TLS and restrict the LAN port to the
proxy source at the firewall.

The complete source documentation remains available under
[`docs/`](https://github.com/ivo-lopes/ivoai/tree/v0.8.0/docs).

## Remote MCP and Web clients

The authenticated `https://YOUR_IVOAI_SERVER/mcp` endpoint supports Streamable HTTP
initialize, tool discovery, safe context reads, scoped Memory tools, OAuth 2.1 with
PKCE, dynamic client registration, and revocation. Content negotiation accepts valid
media-range ordering, whitespace, q-values, wildcards, and Content-Type parameters;
unsupported negotiation returns HTTP 406 and invalid request media types return 415.

See the versioned [ChatGPT Web and Claude Web guide](https://github.com/ivo-lopes/ivoai/blob/v0.8.0/docs/mcp-web.md).

## Install and update

```sh
curl -fsSL https://raw.githubusercontent.com/ivo-lopes/ivoai/v0.8.0/install.sh | sh
ivoai update --dry-run
ivoai update
```

Server operators should back up first, then rerun the idempotent setup after update:

```sh
sudo ivoai server backup
sudo ivoai update --dry-run
sudo ivoai update
sudo ivoai setup --mode server
sudo ivoai server doctor
```

`ivoai update --rollback` restores the previous verified binary and compatible
IVOAI-owned mutable state from the last transaction checkpoint.

## Compatibility and deferred work

- Caveman remains the default requested compression provider; Direct remains the
  safety/effective fallback.
- Headroom remains available for compatibility and rollback.
- OpenCode remains a managed Direct primary and is not added to AUTO/workers.
- Ruflo remains in the currently supported orchestration path.
- OpenViking, NativeOrchestrator v2, full Conversation Continuity, Monitor TUI, and
  other vNext work remain planned rather than shipped.
