# IVOAI v0.9.2

This corrective stable release makes the OpenCode-first AUTO experience operational
for explicit model and reasoning selection, repairs federated Memory/Context results,
and publishes the documentation portal in English and Brazilian Portuguese.

## Model, reasoning, and bridge reliability

- OpenCode's native picker receives the runtime-verified IVOAI catalog, including
  automatic scheduling and eligible Codex and Claude Code model/reasoning choices.
- Explicit selections are passed to the official executor and fail clearly when no
  longer eligible; they never silently fall back to a different model.
- Requested and effective executor, model, reasoning, selection mode, and catalog
  revision are stored as bounded, non-sensitive session metadata.
- The bridge rejects partial or malformed streams and classifies auth, startup,
  timeout, cancellation, executor, MCP, and protocol failures without exposing raw
  executor stderr.

## Memory, Context, and multi-server MCP

- Federated `tools/call` responses use a conformant MCP `CallToolResult` text envelope
  with deterministic source provenance. This fixes the Codex `Unexpected response
  type` failure that surfaced as `ivoai_bridge_error` for Memory/Context prompts.
- Federated initialization drains every in-flight upstream call before returning a
  fail-closed error for stateful upstream sessions. No request continues after the
  router response and no session identifier crosses source boundaries.
- Automatic federation remains bounded to eight selected sources and a shared
  response budget. Writes remain single-destination and credentials remain isolated
  per server identity.

## Documentation and localization

- Native Docusaurus i18n serves English at `/` and Brazilian Portuguese at `/pt-BR/`,
  with localized navigation, search, public product content, and accessibility labels.
- CI validates translation parity, links, search, both themes, responsive layouts,
  200% zoom, keyboard navigation, axe, contrast, and a continuous page canvas.
- The desktop footer keeps only actionable links on one line with the copyright
  directly below. The self-hosted `IVOΛI` wordmark uses the OFL-licensed Bpmf Huninn
  face, with a custom rounded lambda matching the type's visual character.
- The embedded portal remains served by the unprivileged `ivoai-docs.service` on
  `0.0.0.0:7780`; managed OpenCode remains loopback-only.

## Authentication and security

Codex and Claude Code retain ownership of subscription authentication. IVOAI does not
copy provider tokens, cookies, or refresh credentials into OpenCode. Managed OpenCode
uses private state, disables sharing, project overrides, external plugins, and
auto-update, and enforces one authoritative frontend writer.

## Install and update

```sh
curl -fsSL https://raw.githubusercontent.com/ivo-lopes/ivoai/v0.9.2/install.sh | sh
ivoai update --dry-run
ivoai update
```

The in-place update preserves configuration, official-client authentication,
multi-server profiles and secrets, Memory/Context state, skills, session metadata,
and user-owned OpenCode files. Use `ivoai update --rollback` to restore the previous
verified binary and compatible IVOAI-owned mutable state.

## Known limitations

- The official executor owns tool execution and permissions; OpenCode receives
  sanitized lifecycle markers rather than a reconstructed native executor TUI.
- Historical documentation snapshots 0.9.0 and 0.8.0 remain archived in English.
- Headroom and Ruflo remain compatibility paths. OpenViking, NativeOrchestrator v2,
  complete Conversation Continuity, and the complete monitor TUI remain deferred.
