# IVOAI v0.13.0 — prepared incremental release

**Status: preparation only; publication gates pending.** This candidate is based
on `5949f20d238acc1c4108515fc462b88e979537c3` and combines the work in
PRs [#31](https://github.com/ivo-lopes/ivoai/pull/31) and
[#32](https://github.com/ivo-lopes/ivoai/pull/32). No v0.13.0 tag, release,
production deployment, exact-head green CI or distributed-artifact verification
is claimed. The release pipeline must record passing required gates before
publication.

This is a functional backend-first increment, not completion of IVOAI-191 or the
approved migration roadmap. OpenCode remains operational. The experimental
Evidence Gateway remains disabled by default, and the economic gate has not passed.

## Delivered behavior

- **Benchmark admission and observability — IVOAI-198/138.** Empty, missing,
  skipped, malformed, mismatched or invalid measurements fail closed. Each failed
  attempt is retained while independent attempts continue. Reports separate all
  attempts from correctness-matched pairs and provider-reported usage from
  estimates; cached input is a subset of input. Private atomic output retains
  only allowlisted measurements, not prompts, responses or arbitrary stderr.
  Timeouts terminate the disposable process group. Linux `wait4` attribution is
  explicit; maximum RSS is not summed simultaneous process-tree memory.
- **Experimental code Evidence Gateway — IVOAI-199/148/192.** The existing
  prefetch/WorkingContext/ArtifactStore path gains bounded session/scope/generation
  reuse, concurrent deduplication, authorization rechecks, provenance, incomplete
  evidence markers and exact artifact references. Sensitive classifications and
  known credential patterns are rejected before persistence.
  `IVOAI_EXPERIMENTAL_EVIDENCE_GATEWAY=1` is an explicit experiment;
  the default stays off. The library's sealed recovery API does not replace the
  existing client artifact transport policy. General recovery-policy integration,
  Memory/Context/tool-output adapters and task-specific sufficiency remain pending.
- **Informal intake — IVOAI-193.** Bounded nonempty UTF-8 prompts no longer need
  objective/deliverable/acceptance headings. Approval, privilege, executor-choice,
  sandbox, tool grants and final acceptance checks remain authoritative. Ordinary
  orchestrated execution still uses the existing DAG policy; this release does
  not introduce execution without a DAG or adaptive worker-free dispatch.
- **Core-owned executor contracts — IVOAI-192.** Shared executor requests,
  results, failures and traces now live in `internal/core/turn.go`. Compatible
  OpenCode aliases preserve fields, JSON behavior and wrapped error identity.
  Each prepared turn keeps the callback that applies its completion policy and
  the callback that releases its resources. Existing Bridge serialization remains;
  this does not enable parallel primaries within a session. Bridge and model
  Catalog dependencies still remain in the OpenCode adapter. No scheduler,
  tool-grant, failover, executor-argument or persistence-schema replacement is implied.
- **Go toolchain security gate — GO-2026-6809.** Earlier PR #31 (`2ba265cb`)
  and PR #32 (`837a466f`) CI runs passed test/race/documentation/audit/ShellCheck
  checks but failed govulncheck on reachable `crypto/x509` vulnerability
  [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) with Go 1.27.2. This was a
  failed promotion gate, not green CI. The module minimum, source-bootstrap
  versions/checksums, manifest and notice now require Go 1.27.3. The new head
  `5949f20d` includes that correction; its new CI runs remain pending. Historical
  local Go 1.27.3 checks do not replace those runs.
- **Dependency remediation and managed Ruflo profiles.** Reviewed documentation
  and runtime dependency updates remove the recorded advisories without audit
  exclusions. Ruflo remains 3.56.5; its dependency profile is now identified by
  the exact embedded manifest/lock hashes, so a same-version installation can
  receive the corrected graph. Private staged installation runs with npm
  lifecycle scripts disabled; validation precedes atomic wrapper promotion.

The later experiment returning a deterministic local answer to `VERSION` without
invoking a model is **excluded** from this candidate. No RTK, Codebase Memory,
OpenViking or Antigravity runtime adapter,
OpenCode removal, administrative web panel or new compression default is delivered.

## Economic acceptance: FAIL; global matrix: INCOMPLETE

The committed [backend validation report](https://github.com/ivo-lopes/ivoai/blob/5949f20d238acc1c4108515fc462b88e979537c3/release-notes/backend-first-validation.md)
retains four datasets containing **72 real Codex attempts**, including failures
and unfavorable results. These are three-scenario App-prefetch experiments using
identified development test binaries, not a full published-client comparison.

In the final comparison, all 18 attempts met their strict oracles. Input tokens
were 141424 → 133738 and elapsed time 45575 → 45520 ms: **5.43% input reduction
and 0.12% elapsed reduction**, below the predeclared **10%/5%** targets. The subset
economic gate **failed**; the full **16-scenario** gate remains **INCOMPLETE**.
A same-binary control also retained a correctness failure and observed variance.
Earlier candidate failures were not retroactively reclassified after clarification
of the unqualified-symbol prompt.

Provider cache equivalence and independent backend model identity remain unproven.
No warm, cross-worker or whole-client inference savings, monetary cost or quota
consumption are established. Source, binary and harness identities remain those
actually measured; later hardening is validated separately rather than attributed
to earlier inference binaries. Publication as a functional release would not turn
these economic results into a success.

A supplemental [context-accounting diagnostic](evidence/backend-first/candidate-gateway-v3/context-accounting-diagnostic.json)
adds no inference and excludes or rescores no rows. The 7686-token aggregate
A-minus-B difference is concentrated in three pairs totaling 7687 tokens; the
other six sum to -1. Host prompt sizes differ by only 2, 2 and 0 bytes in those
three pairs, with equal source-result byte counts within each pair. The median
of all nine per-pair reductions is approximately 0.020191%. The cause of the
higher provider-reported totals is unexplained, not investigated or attested;
no cache, reuse or model mechanism is identified as responsible. This diagnostic
leaves the failed economic gate unchanged.

## Compatibility, security and rollback

Official clients retain their authentication. This increment introduces no
provider credential extraction, personal client-configuration rewrite or paid
API fallback. Existing session/configuration schemas and public executor wire
fields remain compatible. Caveman remains the default compression provider,
Headroom optional and Direct the fallback; ai-memory and Context remain separate.

The [MIT Zod compatibility fork](https://github.com/ivo-lopes/ivoai/blob/5949f20d238acc1c4108515fc462b88e979537c3/patches/zod3-compat/README.md)
is explicitly `@ivoai/zod3-compat`, with pinned source, patch and archive identity.
It backports upper-bound rejection for V3 collections while preserving patched V4
exports and the V3 consumer API; the four official V4 dependency copies remain
unchanged. Unbounded schemas remain unbounded. npm advisory matching for this
fork name does not automatically follow future upstream `zod` advisories: manual
upstream security review, provenance and regression tests remain necessary until
a suitable upstream fix or validated consumer migration replaces the fork.
No automatic cross-name advisory monitor is implemented. The reviewed patches'
MIT licensing does not certify every transitive artifact's license.

For rollback, retain the previous executable and managed Ruflo wrapper/profile.
Profiles and the legacy flat payload are preserved; failed staging does not
replace the previous wrapper, and named profiles are not repaired in place.
Automatic profile garbage collection is absent, so retained profiles consume
disk. Managed runtime/cache/wrapper paths with symlink ancestors now fail closed.
Only a newly staged contained launcher receives permission normalization; an
unsafe promoted profile is rejected. Idempotent checks validate exact manifests,
wrapper and contained launcher, not every installed `node_modules` byte or
compromise by the same operating-system user.

Restoring an older runtime profile can also restore older vulnerable dependencies;
it is emergency compatibility recovery, not a security remediation. User-owned
third-party installations, credentials and histories remain under their prior
ownership policy. Disabling the Gateway flag restores the existing retrieval
path. Reverting the Core/intake changes requires no stored-data conversion.
Executable/config rollback does not reverse ai-memory or Context database changes;
no production data migration is performed or authorized by this preparation.

## Known limitations and next acceptance work

Claude's administrative probe returned `loggedIn=false`, `authMethod=none`, exit 1;
no Claude inference was attempted. Native Claude parity remains unverified.
Antigravity remains research-only, without verified runtime/TUI integration.
`CONTEXT_SYNC=BLOCKED` remains tied to IVOAI-175; a memory write is not Context
sync. The requested canonical memory pages were unavailable during the audit.

The remaining roadmap includes the complete economic matrix and project/language
mix, real worker/continuity comparisons, recovery-policy integration, adaptive
orchestration, optional adapters, native-client certification, OpenCode retirement
and the administrative backend/panel. No Plane item is marked complete merely
because these partial deliveries exist.

### Comportamento entregue

- **Benchmark e observabilidade — IVOAI-198/138.** Evidências vazias, ausentes,
  puladas, malformadas, divergentes ou inválidas falham de forma fechada. Cada
  tentativa com falha é preservada e as independentes continuam. Os relatórios
  separam todas as tentativas dos pares corretos, uso reportado de estimativas e
  entrada em cache como subconjunto da entrada. A saída privada e atômica contém
  apenas medições permitidas; não guarda prompts, respostas ou stderr arbitrário.
  Timeouts encerram o grupo descartável de processos. A atribuição Linux `wait4`
  é explícita; RSS máximo não é RAM simultânea somada da árvore de processos.
- **Evidence Gateway de código experimental — IVOAI-199/148/192.** O caminho
  existente de prefetch/WorkingContext/ArtifactStore ganha reutilização limitada
  por sessão/escopo/geração, deduplicação concorrente, novas verificações de
  autorização, proveniência, indicação de evidências incompletas e referências
  exatas. Classificações sensíveis e padrões conhecidos de credenciais são
  rejeitados antes da persistência. A flag
  `IVOAI_EXPERIMENTAL_EVIDENCE_GATEWAY=1` habilita um experimento; o padrão continua
  desligado. A recuperação selada da biblioteca não substitui a política de
  transporte de artefatos dos clientes. Adaptadores gerais de Memory/Context/saídas
  de ferramentas, suficiência por tarefa e integração da política de recuperação
  continuam pendentes.
- **Intake informal — IVOAI-193.** Prompts UTF-8 não vazios e limitados dispensam
  títulos de objetivo/entrega/aceite. Aprovações, privilégios, escolha de executor,
  sandbox, grants e verificações finais continuam como autoridade. A execução
  orquestrada ainda usa o DAG existente; esta versão não introduz execução sem DAG
  nem despacho adaptativo que dispense workers.
- **Contratos de executor no Core — IVOAI-192.** Solicitações, resultados,
  falhas e traces compartilhados passam a `internal/core/turn.go`. Aliases OpenCode
  compatíveis preservam campos, JSON e identidade de erros envolvidos. Cada turno
  preparado mantém seus próprios callbacks de política/validação de conclusão e
  liberação de recursos. A serialização existente do Bridge permanece; esta
  alteração não habilita primaries paralelos na mesma sessão. Bridge e catálogo
  de modelos ainda dependem do
  adaptador OpenCode. Não há substituição de scheduler, grants, failover, argumentos
  dos executores ou schema persistido.
- **Gate de segurança da toolchain Go — GO-2026-6809.** Os CIs anteriores dos
  PRs #31 (`2ba265cb`) e #32 (`837a466f`) passaram nas verificações de testes,
  race, documentação, auditorias e ShellCheck, mas reprovaram no govulncheck por
  [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) alcançável em `crypto/x509`
  usando Go 1.27.2. O gate de promoção falhou; não foi CI verde. O mínimo do
  módulo, versões/checksums do bootstrap, manifesto e notice agora exigem Go
  1.27.3. O novo head `5949f20d` inclui a correção, mas seus novos CIs estão
  pendentes. As verificações locais históricas em Go 1.27.3 não substituem esses CIs.
- **Dependências e perfis Ruflo.** Atualizações revisadas da documentação e do
  runtime corrigem os avisos registrados sem exclusões de auditoria. Ruflo continua
  em 3.56.5, mas o perfil de dependências usa hashes exatos do manifesto/lock
  embarcados: a mesma versão pode receber o grafo corrigido. A instalação ocorre
  em staging privado, sem scripts de ciclo de vida npm, com validação antes da
  promoção atômica do wrapper.

O experimento posterior que responde de forma determinística e local a `VERSION`,
sem invocar modelo, está **excluído**.
Esta entrega não inclui adaptadores de runtime RTK, Codebase Memory, OpenViking ou
Antigravity, remoção do OpenCode, painel administrativo ou novo padrão de compressão.

### Aceite econômico: FAIL; matriz global: INCOMPLETE

O [relatório do backend](https://github.com/ivo-lopes/ivoai/blob/5949f20d238acc1c4108515fc462b88e979537c3/release-notes/backend-first-validation.md)
preserva quatro datasets com **72 tentativas reais de Codex**, inclusive falhas e
resultados desfavoráveis. São experimentos de prefetch App em três cenários, com
binários de teste de desenvolvimento identificados, não uma comparação completa
dos clientes publicados.

As 18 tentativas finais passaram nos oráculos estritos. Tokens de entrada foram
141424 → 133738 e o tempo 45575 → 45520 ms: redução de **5,43% na entrada e 0,12%
no tempo**, inferior às metas predeclaradas de **10%/5%**. O gate do subconjunto
foi **reprovado**; o gate global de **16 cenários** permanece **INCOMPLETE**. O
controle com o mesmo binário também preservou falha de correção e variância.
Falhas anteriores não foram reclassificadas após esclarecer o prompt sobre o
identificador de símbolo sem qualificação.

Equivalência do cache do provedor e identidade independente do modelo no backend
continuam não comprovadas. Não se estabelecem economias de inferência com cache
quente, entre workers ou no cliente completo, nem custo monetário ou consumo de
quota. Identidades de binário/harness continuam sendo as realmente medidas;
hardening posterior é validado separadamente. Publicar uma versão funcional não
transforma esses resultados econômicos em aprovação.

O [diagnóstico suplementar de contabilização do contexto](evidence/backend-first/candidate-gateway-v3/context-accounting-diagnostic.json)
não acrescenta inferência nem exclui ou reclassifica linhas. A diferença agregada
A-menos-B de 7686 tokens concentra-se em três pares que somam 7687; os outros seis
somam -1. Nesses três pares, o prompt do host difere apenas 2, 2 e 0 bytes, com
contagens de bytes da fonte iguais dentro de cada par. A mediana das reduções dos
nove pares é aproximadamente 0,020191%. A causa dos totais mais altos reportados
pelo provedor permanece sem explicação, investigação ou atestação; nenhum mecanismo
de cache, reutilização ou modelo é identificado como responsável. O diagnóstico
mantém o gate econômico reprovado.

### Compatibilidade, segurança e rollback

Os clientes oficiais mantêm sua autenticação. Este incremento não extrai
credenciais, reescreve configurações pessoais dos clientes nem habilita fallback
para APIs pagas. Schemas de sessão/configuração e campos públicos dos executores
continuam compatíveis. Caveman permanece padrão, Headroom opcional e Direct como
fallback; ai-memory e Context continuam separados.

O [fork MIT de compatibilidade Zod](https://github.com/ivo-lopes/ivoai/blob/5949f20d238acc1c4108515fc462b88e979537c3/patches/zod3-compat/README.md)
é explicitamente `@ivoai/zod3-compat`, com origem, patch e arquivo fixados. Ele
antecipa a rejeição de coleções V3 acima do limite e preserva exports V4 corrigidos
e a API V3; as quatro cópias oficiais V4 permanecem inalteradas. Schemas sem teto
continuam sem teto. O matching de avisos npm para esse nome não acompanha
automaticamente futuros avisos de `zod`: revisão manual upstream, proveniência e
testes seguem necessários até substituição por correção upstream adequada ou
migração validada dos consumidores. Não há monitor automático entre os nomes.
A licença MIT dos patches revisados não certifica a licença de todo artefato transitivo.

Para rollback, preserve o executável e o wrapper/perfil Ruflo anteriores. Perfis
e payload legado são mantidos; falhas de staging preservam o wrapper anterior e
perfis nomeados não são reparados no lugar. Não há coleta automática de perfis,
que consomem disco enquanto retidos. Caminhos gerenciados de runtime/cache/wrapper
com ancestrais symlink agora falham de forma fechada. Só um launcher contido em
staging novo recebe normalização de permissões; um perfil promovido inseguro é
rejeitado. A idempotência verifica manifestos exatos, wrapper e launcher, não cada
byte de `node_modules` nem comprometimento pelo mesmo usuário do sistema operacional.

Restaurar um perfil antigo também pode restaurar dependências vulneráveis; é
recuperação emergencial de compatibilidade, não correção de segurança. Instalações,
credenciais e históricos de terceiros pertencentes ao usuário mantêm sua política
de propriedade. Desligar a flag do Gateway restaura a recuperação existente.
Reverter Core/intake dispensa conversão de dados. Rollback de executável/configuração
não reverte bancos de ai-memory/Context; nenhuma migração de dados em produção
é realizada ou autorizada por esta preparação.
