# v0.10.3 — Conversation Continuity

- Fix the native `/resume` picker in `ivoai codex`: authenticated discovery connections have isolated request IDs and response routing; cancelling the picker keeps the primary alive.
- Keep sandbox enforcement on the owned App Server, avoiding remote-TUI permission overrides that also blocked native selection on Codex 0.154.0.
- Preserve a stable IVOAI session identity across restart and native resume, with separate frontend and official-provider mappings. Managed Codex history survives private runtime cleanup without copying personal configuration or authentication.
- Add `session resume`, `session recover` and explicitly confirmed `session handoff`, also available from the TUI Session Control. Frontend switching does not silently change the provider; direct and orchestrated modes stay distinct.
- Reconcile approved interrupted DAGs against the repository, task states, process ownership and collected worktrees. Completed tasks do not repeat; ambiguous mutations fail closed. Remaining execution requires fresh approval, current routing and fresh MCP grants.
- Keep a bounded private continuity checkpoint and handoff brief, with lineage and no raw transcript, worker prompt, reasoning or credential persistence in the continuity journal.
- Preserve v0.10.2 configuration, server profiles, MCP registry, Skills/Ponytail, Prompt Gate, plan approval, economic routing, worktrees and OpenCode input/clipboard behavior.

Native history deleted by older ephemeral frontends cannot be reconstructed from
metadata. Unobserved or ambiguous direct-provider mappings are not guessed.
Cross-provider handoff transfers bounded context, not a native transcript.
OpenCode Full Console, OpenViking and advanced parallel orchestration remain out
of scope. The next planned feature release is v0.10.4 — OpenCode Full Console.
