# IVOAI v0.9.1

This corrective stable release makes the OpenCode-first AUTO experience operational
for explicit model and reasoning selection, repairs federated Memory/Context results,
and publishes the documentation portal in English and Brazilian Portuguese.

## Model and reasoning selection

- OpenCode's native model picker now receives the runtime-verified IVOAI catalog.
  It exposes automatic scheduling plus eligible Codex and Claude Code choices.
- Supported reasoning variants come from each official client capability. An explicit
  model or effort is passed to that official executor and fails clearly when it is no
  longer eligible; explicit choices never silently fall back to another model.
- Requested and effective executor, model, reasoning, selection mode, and catalog
  revision are stored as bounded, non-sensitive session metadata and remain visible
  in the managed IVOAI panel.
- Model changes start a compatible executor thread instead of resuming a thread that
  belongs to a different model.

## Executor bridge reliability

- The bridge classifies auth, startup, timeout, cancellation, non-zero exit, malformed
  stream, and protocol failures without exposing executor stderr or accepting partial
  output as a final answer.
- Malformed JSON events fail closed. Non-streaming partial output now also prevents
  quota failover from launching the same task a second time.
- Managed OpenCode readiness requires the complete IVOAI provider catalog, and a
  private cross-process lease enforces one authoritative managed frontend writer.
- OpenCode remains pinned to 1.18.25, bound to random loopback ports, with sharing,
  project overrides, external plugins, and auto-update disabled only in managed mode.

## Memory, Context, and multi-server MCP

- Federated `tools/call` responses now use a conformant MCP `CallToolResult` text
  envelope with deterministic source provenance. This fixes the Codex
  `Unexpected response type` failure that surfaced as `ivoai_bridge_error` for
  prompts consulting both Memory and Context.
- Initialization reaches every selected stateless source. Stateful upstream session
  identifiers fail closed instead of being copied between independent sources.
- Automatic federation remains bounded to eight selected sources and a shared
  response budget. Tool discovery degrades to another healthy source, while writes
  remain single-destination and credentials remain isolated per server identity.
- Upstream transport errors returned to models are sanitized; raw internal endpoints
  and credentials are not included.

## Documentation and localization

- The native Docusaurus i18n pipeline now builds English at `/` and Brazilian
  Portuguese at `/pt-BR/`, with a keyboard-operable locale selector, localized
  navigation, search, product content, and accessibility labels.
- All 44 current public documents and the frozen 0.9.1 snapshot have pt-BR parity.
  CI validates document sets, code blocks, and link destinations for translation
  drift. Historical 0.9.0 and 0.8.0 snapshots predate localization and remain archived
  in English.
- The light and dark document canvas now resolves through one semantic token across
  the root, main wrapper, sidebar, and table of contents. This removes the dark-mode
  horizontal background seam while retaining distinct code, card, and admonition
  surfaces.
- Playwright and axe cover both locales, both themes, representative pages, four
  responsive widths, 200% zoom, keyboard navigation, localized search, version and
  locale composition, real computed code-comment contrast, and canvas continuity.
- On desktop, the footer keeps only its actionable links on one aligned row, with
  the centered copyright notice directly beneath; mobile remains responsive.
- The visual wordmark is now `IVOΛI`, set in the self-hosted, OFL-licensed Bpmf
  Huninn face. Product names, commands, metadata, and legal text remain `IVOAI`.
- The embedded static portal remains served by the unprivileged `ivoai-docs.service`
  on `0.0.0.0:7780`; the managed OpenCode backend remains loopback-only.

## Authentication and security

Codex and Claude Code still own their subscription authentication. IVOAI does not
read or copy provider tokens, cookies, or refresh credentials into OpenCode. Catalog
entries and terminal-facing strings reject control and bidirectional characters,
capability caches are private regular files, listener announcements reject URL
userinfo, and multi-server tokens never cross source boundaries.

## Install and update

```sh
curl -fsSL https://raw.githubusercontent.com/ivo-lopes/ivoai/v0.9.1/install.sh | sh
ivoai update --dry-run
ivoai update
```

The in-place update preserves configuration, official-client authentication,
multi-server profiles and per-server secrets, Memory/Context state, skills, session
metadata, and user-owned OpenCode files. Use `ivoai update --rollback` to restore the
previous verified binary and compatible IVOAI-owned mutable state.

## Known limitations and deferred roadmap

- The hidden official executor owns tool execution and permissions; the OpenCode UI
  receives sanitized lifecycle markers rather than a second, reconstructed native
  executor TUI.
- Historical documentation snapshots 0.9.0 and 0.8.0 are available in English; full
  native localization starts with the current and 0.9.1 documentation sets.
- Headroom and Ruflo remain compatibility paths. OpenViking, NativeOrchestrator v2,
  complete Conversation Continuity, and the complete monitor TUI remain deferred.
