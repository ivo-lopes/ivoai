# IVOAI v0.9.6

## Codex AUTO in administrative workspaces

Managed AUTO supports directories outside Git using the official Codex
`exec --skip-git-repo-check` option, including resume. Root configuration and
exec-only arguments have separate ownership, preventing misplaced or duplicate
managed flags. IVOAI does not create repositories, change global trust, alter
provider authentication, disable sandboxing, or accept partial output as success.

## Conservative legacy Memory migration

Setup/update no longer installs the obsolete global local `ai-memory` MCP alias.
An existing exact historical entry is migrated only with matching IVOAI component
ownership and an IVOAI-owned hook reference. Customized/unproven personal MCPs are
preserved. Migration is idempotent, records a private receipt containing only the
removed public entry, and leaves unrelated configuration and spool data untouched.
Normal session launches do not perform permanent global Codex configuration edits.

Memory hooks retain their single-purpose, single-destination contract. Ambiguous
destinations fail without write fan-out or replaying queued events.

## Turn failures and multi-server diagnostics

- Bounded turn-attempt metadata is persisted before a native thread exists.
  Known pre-thread errors retain a classified cause, including
  `non_git_repository_gate`; arbitrary stderr and conversation text are not saved.
- `turn_state` / `executor_exit_code` are separate from `frontend_state` /
  `frontend_exit_code`. Closing OpenCode normally cannot erase a failed turn.
- Status, Doctor and Memory status use configured server profiles and authenticated
  MCP read probes. Memory/Context read health is separate from hook destination
  ambiguity; empty valid Context results remain valid.
- List/show explicitly report `not_probed`. Existing booleans remain compatible,
  with additive state/probed fields to distinguish unknown from unhealthy.
  `ivoai status --json` exposes the Doctor report envelope.

## Upgrade and boundaries

Use `ivoai update` and inspect `ivoai doctor`, `ivoai memory status`, and
`ivoai connect server test <alias>`. The official updater retains its snapshot,
rollback and reapply contract. No re-enrollment or provider credential copying is
required. Personal MCP entries whose provenance cannot be established require
operator review rather than automatic deletion.

This patch covers IVOAI-125, IVOAI-126 and the F3/F4 diagnostics of IVOAI-52.
It does not change the multi-server registration TUI (IVOAI-123), compression
policy, bundled sandbox dependencies, or the future orchestration roadmap.
Claude Code remains an optional supported capability.
