# Subscription-route projection: synthetic preparation, not client qualification

This increment adds two test-only files to prepare a bounded, host-only route check for the direct economic benchmark. It does not connect the helper to the live harness, launch an official client, submit a model question or change production Go. `Connected=false` and `ACCEPTED_UNQUALIFIED` distinguish acceptance of synthetic response data from client or subscription certification.

The candidate is based on `e4250ab0497f4366cb80b7ce03aa21608f58dd34`. The same two files were projected byte-for-byte onto the existing v0.12.1 compatibility source `b45354791f1d28632e8094b82d1fe5f9c568eba1`, committed locally as `378d9075c500a41163a7d496815070600ff4ce9b`. The [source identity receipt](evidence/subscription-route-projection/v3-source-identity.json) verifies all589 existing candidate Go paths and493 baseline Go paths unchanged. No modules, pins, workflows, website/embed or authored CLI-reference inputs changed.

## Prepared behavior

The private plan reuses `prefetchDirectScope` and its directory, explicit environment, trust settings and feature restrictions. It admits only the reviewed common constructor shape, copies slices before callbacks and rejects scope changes at the transport boundary. Probe, MCP inventory and exec construction receive the same host-owned `model_provider="openai"`, canonical ChatGPT `openai_base_url` and `chatgpt_base_url`. The synthetic test retains both user/system MCP disable settings in exec. It includes normal user configuration in the shared scope and adds no `--ignore-user-config` flag.

The helper does **not** add `respect_system_proxy=false`, alter institutional network policy or infer that filtering a proxy is allowed. This prepared environment profile requires an explicit host declaration that the filtered environment is permitted. An unknown or required incompatible proxy policy stops before transport. The declaration is benchmark eligibility, never a model-supplied field, client permission or proof that policy was discovered automatically.

The RPC adapter accepts an injected owned session. It prepares initialize with the experimental capability needed for the routing field, followed by config/read with layers disabled and the exact fixture cwd, configRequirements/read, and account/read with refreshToken=false. It stops after any refusal and closes the owned session. No concrete stdio launcher is implemented or wired here: the existing Facade rewrites the provider to IVOAI, so reusing it would measure a different route. A concrete existing-lifecycle adapter and the exact official-client recipe require their own review and offline qualification.

Accepted response size is2MiB, depth32,32768 value nodes and128KiB per string. Reads use at most one extra byte to detect overflow. Duplicate keys, including escaped aliases, malformed/truncated/extra messages, response-ID mismatch, unknown RPC version, remote errors, partial reads and no-progress streams produce closed error enums. A concrete transport must also cancel blocked reads and reap its child; interface-only tests do not prove those lifecycle properties.

Effective configuration can contain credentials, headers and command metadata. Raw bytes exist only in bounded host RAM and are cleared when parsing finishes; decoded Go strings are reclaimed normally, with no claim of cryptographic memory erasure. Full maps are local to the host projection and do not enter the admission, errors, logs, model context, evidence storage or raw-config hashes. JSON/String/GoString rendering exposes only closed enums and booleans. Tests use synthetic private-value sentinels in unused providers and account metadata to check those outputs.

The first predicate requires the builtin provider and exact canonical URLs, observable absence/null of user forced-login/workspace restrictions, compatible known requirements, ChatGPT-compatible account metadata and a canonical workspace origin with `NO_CONSTRAINT`. It refuses custom/API/unknown routes and non-null unknown requirements. A policy permitting both API and ChatGPT login remains compatible when the observed account separately passes the ChatGPT gate; permission to use API is not an API execution request. Non-null requirements must expose the pinned effective login-method field. This conservative first profile can refuse legitimate policies or regional routing until their contracts are reviewed; it never disables them to obtain acceptance.

## Pinned source and material limits

The [official source record](evidence/subscription-route-projection/official-source-contract.json) binds the inspected `rust-v0.162.1` tag to commit `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`. This is source provenance, not an ELF rebuild attestation.

- A reserved builtin provider can still receive top-level `openai_base_url`; selecting `openai` alone is insufficient. The canonical inference URL is defined in [model-provider-info](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/model-provider-info/src/lib.rs).
- Forced login is not a safe guard to add: the pinned [auth manager](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/login/src/auth/manager.rs) can remove saved credentials on a mismatch, and exec invokes that enforcement. This helper neither adds restrictions nor invokes login/logout.
- `Config` uses snake_case, while `ConfigRequirements` uses camelCase in the [protocol](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/app-server-protocol/src/protocol/v2/config.rs). `NO_CONSTRAINT` has an explicit serialization override in the account protocol.
- Account type ChatGPT is a [provider-visible union](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/model-provider/src/provider.rs), not exclusive proof of interactive subscription credentials. No subtype, model availability, quota or effective backend is certified.
- Normal client-owned OAuth refresh/cache maintenance is supported behavior, not agent extraction, sharing or rotation of credentials. refreshToken=false does not prohibit normal discovery/recovery. The [routing implementation](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/app-server/src/request_processors/account_processor/workspace_routing.rs) can discover another origin; startup auth/cloud work precedes the projection.
- Pre-prompt is not pre-network. Managed requirements can outrank CLI settings, and policy/config/auth can change between probe and exec. Identical host settings and scope do not provide an atomic snapshot or universal startup/cloud/system egress certification. A detected conflict stops without prompt, retry, paid fallback or policy bypass.
