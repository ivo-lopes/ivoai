# v0.10.2 — Managed frontend recovery hotfix

This is a corrective release for v0.10.1, not the OpenCode Full Console release.

- Restore setup and upgrade of the IVOAI-managed OpenCode artifact. Release metadata now uses the existing checksum-only promotion tier, without weakening integrity policy or claiming upstream signatures for a rebuilt binary.
- Stop native Codex App Server descendants before private-directory cleanup, and disable its independent plugin plane. IVOAI remains the authority for Skills/capabilities.
- Prevent Codex exec's App Server from persisting inferred project trust during workspace-write tasks. Managed primary/workers use an explicit process-local untrusted project entry, retaining their sandbox and official authentication without modifying personal configuration.
- Return actionable pending-primary state instead of waiting for the coordinator's own unfinished task. Acceptance and explicit primary completion remain mandatory before integration and synthesis.
- Harden native smoke synchronization so input is sent after the composer is ready, not merely after the startup banner.

The v0.10.1 tag and assets remain immutable. Existing profiles, MCP secret references, permission settings and provider-owned authentication remain compatible. Codex Direct and OpenCode Direct remain available. No Full Console features are included.

## Notes

Native Codex uses the upstream remote App Server protocol, which remains experimental. Live Wayland verification requires a Wayland session; X11 and backend fixtures do not certify an unavailable desktop session.

# pt-BR

Hotfix corretivo da v0.10.1; não entrega OpenCode Full Console.

- Corrige setup/upgrade do OpenCode gerenciado usando o nível de checksum já aceito pela política, sem alegar assinatura upstream do binário reconstruído.

Tag/assets da v0.10.1 permanecem imutáveis. Profiles, referências de segredos MCP, permissões, autenticação oficial e modos Direct permanecem compatíveis. Nenhuma feature do Full Console foi iniciada.
