## Documentation follow-up audit

The later documentation checkout passed its frozen EN/PT build and embedded-site
comparison, CLI reference, full Go tests/vet and 26 portable utility tests. The
production docs audit passed the unchanged `high` threshold with **zero high or
critical**, while reporting **one low**. The separate low-threshold invocation
returned exit 1 as expected; it was retained rather than suppressed.

The residual is deepmerge 4.3.1, [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4)
(CVE-2026-93753). The official advisory rates prototype poisoning of returned
objects low, affects 4.2.0–4.3.1 and lists no patched version at the observed date.
The local dependency route is Docusaurus preset→SVGR webpack/plugin-svgo→deepmerge,
a Node documentation-build chain. The plugin-svgo 8.1.0 package declares the dependency, but its installed entry
does not import/call it; it obtains SVGO config and calls
svgo.optimize. SVGO 3.3.5 itself does not declare deepmerge.

The Go docsserver serves embedded files without Node or runtime SVG conversion.
No path from Go HTTP/browser input to the affected merge function was demonstrated
in this scoped review. This is not a universal bundle-safety claim or an upgrade
to critical severity. Dependencies, thresholds and suppressions were unchanged.
See the [audit/triage receipt](evidence/v0.14.0-publication/deepmerge-low-triage.json).
Historical v0.12/v0.13 zero-audit statements remain snapshots of their epochs;
they are not reused as the current audit result.
