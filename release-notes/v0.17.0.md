# IVOAI v0.17.0 — backend-first native execution and administration

## User-visible changes

- Managed Codex accepts natural requests through the Core. The opt-in adaptive
  Primary answers simple requests without a DAG and uses the existing planning,
  approval and worker protocol when a task needs them. Native exit, multiple
  turns and eligible cross-process resume retain admission and NoReplay checks.
- Official Codex 0.167.0 and its exact companion are reviewed alongside the
  previously certified 0.166.0 and 0.162.1 pairs. Adaptive certification remains
  Linux amd64 with exact hashes; the feature is not globally enabled.
- The optional native read-only Code Intelligence Gateway reuses exact evidence,
  invalidates changed sources and checks authorization on cache hits and recovery.
  Enable it only through its documented experimental flag.
- The administrative web console uses the same backend, with authentication,
  authorization, explicit mutation confirmations, audit, sanitized bounded output,
  revocation/logout and reverse-proxy/TLS publication. It adds no chat frontend.
- Optional Antigravity 1.5.2 headless execution shares Core admission, sessions,
  tools and workers. Real official two-turn, permission-denial and approved DAG
  integrations passed. This does not claim transparent native TUI control.
  The reviewed executable requires PCLMULQDQ. Startup passed on emulated CPUs
  with that feature and AVX/AVX2 disabled; an incompatible CPU is now rejected
  before client discovery, lease creation or an execution attempt.
- Optional Claude headless integration uses the official supported interface and
  the same Core. Protocol checks use an isolated synthetic provider; real Claude
  subscription inference remains pending because the user has no account.
- Managed OpenCode installation, repair, probing and execution are removed.
  `ivoai auto` enters managed Codex. Old entry points return explicit migration
  errors. Existing personal binaries, configurations, credentials and histories
  are retained; legacy wire contracts remain readable.

## Dependencies and recoverability

Reviewed runtime and JavaScript locks are refreshed, including ai-memory 3.4.2,
Qdrant 1.20.0, Headroom 0.43.1, Ruflo 3.72.2, pnpm 12.18.0 and Playwright 1.65.0.
Python remains 3.14.10, the latest compatible reviewed runtime: the 3.15.2 probe
failed on a required PyYAML wheel and is preserved as an unsupported combination.
Unchanged dependencies retain their verified pins rather than being repinned
without a version change.

`UV_OFFLINE=1` explicitly allows Headroom installation/reapplication from its
reviewed cache while retaining the isolated environment, wheel hashes, constraints
and forced installation. Missing cache fails without publishing a launcher.
The complete stable-upgrade gate uses this mode only in its network-isolated
phase; cache preparation remains online. The initial unsuccessful reapplication
and the successful focused/cache-miss reproductions are retained as evidence.

Caveman 4.0.2-ivoai.1 is an IVOAI Apache-2.0 rebuild of reviewed upstream source
with repaired Go dependencies. Both rebuilt binaries passed vulnerability scans;
upstream vulnerable executables are not installed as a fallback. Source, patches,
archive identity and notices are bound into release metadata. This local rebuild
is not an upstream signature. Caveman stays the default when eligible, Headroom
optional and Direct the explicit safe fallback; authoritative memory/context
bypass destructive compression.

Server dependency migration requires stopped services, private snapshots of data
and index, isolated old/new validation and explicit activation. Rollback restores
Memory into an empty tree and preserves forward-only files in quarantine. A real
private Memory2.6.3→3.4.2→2.6.3/Qdrant1.19.2→1.20→1.19.2 cycle passed, including
exact restored names/hashes before restart. Memory, index and config activation
are not one atomic transaction: an interrupted later step can require manual
recovery with services stopped and snapshots/quarantines retained. Production
systemd and resource-limit enforcement are separate operator validations.

Use the retained previous Core/profile and the original verified v0.16.0 assets
for rollback. Historical tags, asset bytes and benchmark outcomes are unchanged.
The current twelve-file bundle replaces the former OpenCode assets with the
reviewed Caveman archives and metadata; the old bundle verifier remains separate.

## Validation and limits

Source-bound evidence covers official Codex DAG/resume and the integrated
three-turn public Gateway flow, plus a separate real cached-receipt revocation
flow. The latter denies presentation/recovery after owner revocation even when
native inference completes; duplicates create no new attempt. Administrative
browser checks include actual local OAuth/Store and TLS proxy flows. Native CPU
startup/emulation, real installers, negative artifact controls, Go tests/race,
vulnerability scans, migration and rollback gates retain their own scopes.
Emulated startup does not certify native ARM inference or adaptive ARM sessions.

Both unfavorable and passing attempts remain recorded. A rejected live admission
or skipped opt-in test is not counted as successful inference. The release
workflow requires native AMD/ARM builds, exact final-bundle upgrade/rollback and
local plus downloaded draft-asset verification before publication.

**Global economic gate: INCOMPLETE.** The separate 54-attempt cohort contains two
failures and worse input/time in its comparable subset; no aggregate savings are
claimed. Cache hits and smaller tool output are not billed-session savings.

Mindsite Context synchronization remains BLOCKED under IVOAI-175 until an
operator-fed ingestion and retrieval are proved for that shared service. Agent
sessions keep Context read-only. Private Context certification does not imply
shared-service synchronization. Optional providers and unproved client parity
remain feature-flagged; no paid API fallback or subscription credential copying
is introduced.
