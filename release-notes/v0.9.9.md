# IVOAI v0.9.9

## Native shared capabilities

- A release-pinned declarative pack from thirteen curated sources is materialized
  through the existing immutable supply-chain store and provider-neutral registry.
- Codex and optional Claude workers select relevant capabilities lazily, after
  prompt/plan gates, dependency/conflict resolution and policy checks.
- Matt Pocock Skills joins the catalog with a bounded domain-modeling subset.
- Personal entries are not adopted or removed merely because their URL or name
  matches a curated source. Local digests are not represented as signatures.

## Ponytail and management

- Ponytail defaults to auto for implementation workers only, with high-risk tasks
  excluded. Off/on are persistent, without authority over acceptance or routing.
- Skills & Capabilities in the `ivoai` TUI shares list/inspect, update, enable,
  disable, pin/unpin and rollback operations with the CLI.
- OpenCode shows selected capability IDs and Ponytail state per worker, not bodies.

## Upgrade and boundaries

Use `ivoai update` from v0.9.8. Existing server profiles, external MCP credentials,
permission mode and orchestration settings remain intact. `ivoai skills update`
reconciles the reviewed baseline from the installed release, never a floating HEAD.

Availability does not authorize execution. High-risk/tool-dependent entries remain
subject to policy; Codex Security is Codex-only. Upstream executable helpers are not
bundled or run, so helper-dependent workflows can remain unavailable. Full mode
does not bypass these boundaries. No token-saving percentage is claimed.

This release does not implement Unified MCP Control Plane, OpenCode Full Console,
OpenViking or Conversation Continuity.
