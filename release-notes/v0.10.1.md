# IVOAI v0.10.1

## Managed OpenCode UX

- Enter submits; Shift+Enter inserts a newline in supported enhanced-keyboard
  terminals. Managed process-local negotiation preserves prior terminal settings.
- Minimal desktop environment propagation restores native X11/Wayland clipboard
  access. The managed OpenCode build propagates backend failures instead of
  reporting success merely after emitting OSC52. Native clipboard writes are bounded.
- Personal OpenCode and terminal configuration remain unchanged.

## Native Codex TUI, IVOAI orchestration

- `ivoai codex` opens the upstream native composer directly, without an IVOAI
  pre-composer. A private App Server façade enforces first-turn prompt admission
  and uses the shared orchestration core through a process-local Responses adapter.
- Native questions handle plan and routing approvals; synthesis appears in the
  conversation. Model/reasoning selection constrains the primary, not every worker.
- DAG dispatch, Codex/optional Claude workers, economic routing, worktrees,
  Skills/Ponytail, quota conservation and `--direct` remain available.
- No account credential is copied into the façade or native frontend; provider
  authentication remains owned by official worker executors.

## Unified MCP Control Plane

- Configure once in IVOAI; use the shared registry from Codex, Claude and managed
  OpenCode projections. TUI and CLI expose inventory, health, enable/disable,
  tool approval policy and conservative Direct policy.
- Exact per-task tool grants replace server-wide external worker grants.
  Mutating/unknown tools require explicit approval, including in Full or immediate
  execution mode. Unrelated tools remain denied.
- Independent revocable worker gateways retain upstream secrets in IVOAI and
  filter tool discovery. The primary cannot inherit delegated workers' grants.
- Existing profiles, registry IDs, secret references and orchestration settings
  remain compatible; no provider login or re-enrollment is required.

## Compatibility boundaries

The pinned Codex 0.153.4 and tested 0.154.0 support native remote TUI/App Server.
The upstream WebSocket interface remains experimental. Orchestrated history is
session-local; persistent upstream resume/fork and global configuration writes are
not exposed by the façade. Use `--direct` for unsupported native operations.

Terminals that encode Enter and Shift+Enter identically cannot be distinguished
by the application. Use a supported enhanced-keyboard terminal; IVOAI does not
require Ctrl+J or alter global emulator settings. OSC52-only delivery is unconfirmed,
not a verified desktop copy. X11 was tested on the development desktop; Wayland
requires a live Wayland session and a functional native backend such as wl-copy.

The managed OpenCode build is 1.18.25-ivoai.1 with a narrow reviewed clipboard
patch, immutable source/patch digests, and architecture-specific release assets.
Claude live testing is optional when not authenticated. OAuth and the full
OpenCode console are not added in this release.
