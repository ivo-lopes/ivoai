# IVOAI v0.10.0

## One orchestration core, multiple frontends

- `ivoai codex` now opens an IVOAI-controlled Codex-oriented terminal. Prompt
  admission is enforced before the official structured Codex executor runs.
- `ivoai opencode` is the canonical managed OpenCode orchestrated frontend.
- `ivoai auto` remains a deprecated compatibility alias, with a stderr warning.
- Explicit `--direct` modes preserve official Codex and standalone OpenCode.
  Claude's existing command and optional worker capability remain available.

## Shared policies and automatic dispatch

Both frontends reuse Prompt Gate, purpose-auto, native DAG, explicit plan approval,
economic routing, host-aware concurrency, isolated worktrees, native Skills and
Ponytail, per-worker MCP policy, quota conservation and primary synthesis.
The scheduler automatically queues delegated work after approval. Codex is the
preferred strong primary in its frontend; eligible workers can use Claude.
Material primary changes require confirmation rather than silent fallback.

## Management and compatibility

The main TUI offers orchestrated frontends and explicit direct sessions. Session
metadata separates frontend, orchestration mode, primary provider and worker
executor. Existing configuration, profiles, credentials, MCP registry, Skills and
Ponytail settings remain intact. No provider login or re-enrollment is required.

Upgrade with `ivoai update --dry-run`, then `ivoai update`. Use the official
transactional rollback command when needed; immutable release tags are not moved.

## Known boundaries

The Codex-oriented terminal is an IVOAI interaction layer, not the upstream Codex
TUI. Enter multiline input with `/submit`, and answer decisions with `/approve`
or `/reject`; use `--direct` for the upstream TUI. OpenCode startup failure now
fails closed instead of opening an ungated direct client. Claude live validation
is optional when not configured. Unified MCP Control Plane and the full OpenCode
console are not part of this release.
