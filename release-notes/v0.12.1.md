# IVOAI v0.12.1

Compatible runtime reliability and retrieval corrections from PR #30. This release
preserves managed Graft, executor compatibility, policy grants and reviewed component versions.

## Corrections

- Bound exact code retrieval and preserve physical source positions despite Go line directives.
- Include the actual Go package in bounded API declaration evidence and expose targeted MCP contracts for simple API queries.
- Preserve worker tool grants and retain failed attempts in local cost estimates.
- Record sanitized operation, schema and result-size evidence without private prompts or responses.
- Classify OpenCode catalog loading, empty/partial results, authentication, communication and stale-cache failures. Retry transient states within the existing deadline; preserve cancellation and reject redirects.

## Validation and known limitations

The runtime candidate at e6f519aa passed all 15 CI jobs, including tests, race,
vet, vulnerability/dependency checks, managed Graft/OpenCode on amd64 and ARM64,
and installation/upgrade/rollback checks. A real OpenCode → IVOAI → Codex smoke
passed without repository or personal-configuration mutations. Local cache and
concurrency tests observed warm p95 19 ms and eight isolated responses with two
structural processes and six cache hits.

**Economic acceptance has not passed.** Publication proceeds following the
maintainer's explicit instruction after receiving the failed-gate report; it does
not reclassify the benchmark as successful. In the final API schema ablation,
B passed 3/3 and A 2/3. Correctness-matched pairs increased input tokens by 10.67%
and elapsed time by 27.77%. Both arms used the candidate runtime with different
schema exposure, not a full published-v0.12.0 comparison. The full 16-scenario
comparison and global cross-worker evidence sufficiency/reuse remain incomplete.
No general token or latency reduction is claimed. Historical results are retained
in [the validation report](https://github.com/ivo-lopes/ivoai/blob/v0.12.1/release-notes/economic-runtime-validation.md).

The historical intermittent OpenCode readiness timeout has no confirmed root
cause; bounded recovery and diagnostics are tested. Official Codex interfaces
confirm client model/effort selection, not independent backend inference identity.
Claude compatibility remains contract-tested; IVOAI-188 awaits real Claude access.

## Compatibility, update and rollback

Managed component versions remain unchanged from v0.12.0. The upstream repository
rename to trailhq/Trail-Code changed the source archive root prefix. A comparison
against the previously pinned archive verified all 391 normalized entries, contents,
modes and links unchanged. The same upstream commit is retained; the newly reviewed
archive SHA-256 is d39598390324ad0076a88ab593b63ad2ba352370ea07c073e31f11327979f8e1.
Build provenance now records this archive; checksum enforcement is unchanged.
Linux amd64 (including the baseline without AVX/AVX2) and ARM64 remain supported.
Use existing IVOAI update and rollback interfaces. Staging, checksum verification,
atomic promotion and previous-version retention remain in effect. Personal
configuration and server profiles retain their ownership boundaries. No database
migration is introduced; executable rollback never substitutes for database
recovery. No production deployment is included.
