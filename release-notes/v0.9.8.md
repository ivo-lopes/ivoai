# IVOAI v0.9.8 — Prompt Gate and Economic Orchestration

## Prompt-driven native AUTO

The managed OpenCode frontend now admits structured work through a mandatory
Prompt Quality Gate. An objective, expected deliverable and observable acceptance
criteria are required; Markdown headings are not. Insufficient prompts wait for
refinement without starting a DAG or workers.

IVOAI owns the native task DAG, dependency admission, worker lifecycle, integration
and final-result gate. Plan approval is required by default. The persistent
`plan_execution=immediate` option skips plan confirmation, not prompt readiness or
security policy. Simple read-only tasks can remain primary-only.

## Economic workers and bounded concurrency

The primary defaults to a strong runtime-verified model. Workers resolve the
minimum sufficient capability tier, model and reasoning from the official runtime
catalog, with quota and task policy constraints. No example model ID is hardcoded
as a routing rule. Codex and eligible optional Claude workers can share a DAG;
unavailable Claude authentication does not block another eligible executor.

Concurrency considers dependency-ready nodes, CPU, available memory, load,
observable I/O pressure and the user cap. Read, implementation, review, security,
documentation, ops and synthesis roles carry distinct capability requirements.
Explicit incompatible executor/model/effort choices fail closed.

## Purpose routing and minimal worker context

AUTO defaults to `purpose-auto`, selecting relevant alias/purpose labels before
institutional lookups. `all-enabled` remains available for compatibility;
`explicit-only` and session `--knowledge-source` overrides are supported.

Workers receive local objectives, acceptance, constraints and relevant references,
not the primary's complete prompt/context. MCPs are deny-by-default per worker.
Approved tools use private process-local projections; credentials remain in their
owning IVOAI/client stores and never enter worker prompts or persisted metadata.
External worker MCP writes are not inferred from Full permission mode.

## Isolated implementation and validation

Independent writers use owned branches/worktrees. Dependency changes are available
to downstream controlled tasks; IVOAI checks collected paths and integration.
Conflicts retain recovery evidence rather than being silently resolved.

If worktrees cannot initialize, execution degrades visibly to sequential checked
patches: workers remain read-only, and IVOAI validates and applies bounded diffs
under an exclusive lease. No automatic `git init` is performed. Failed or
incomplete DAGs cannot be presented as successful final responses.

## Approvals and operational UI

At 10% remaining quota or below, conservation requires confirmation. A material
provider/model/effort change has its own approval; the primary remains strong by
default. Full tool permissions do not approve a plan or a routing change.

The `ivoai` orchestration menu exposes plan approval, concurrency/cap, parallel
writes, knowledge routing, provider preference and low-quota threshold. OpenCode
shows bounded plan, worker, routing, purpose and quota metadata, without private
worker transcripts. Deterministic presentation goldens include approval, parallel
workers, conservation and sequential degradation states.

## Upgrade and limitations

Use `ivoai update` through the checksum-verified updater. Existing multi-server
profiles, stable credential references, external MCP authentication, permission
mode and official provider login ownership are preserved; no re-enrollment is
required. New orchestration settings apply to the next managed session.

Purpose selection is conservative and label-based, not an unrestricted semantic
organization classifier. Use explicit sources for ambiguous prompts. Unknown quota
is not unlimited quota, and unverified model/writer capabilities are ineligible.
Sequential patch fallback refuses sensitive paths, symlinks, binary diffs and
unsupported mode changes. Conflicts and incomplete validation remain failures.

The DAG is session-local; this release does not add durable conversation
continuity, the full OpenCode console, OpenViking, Ponytail or a new native Skills
pack. Claude Code remains supported and optional. Skills/Ponytail work belongs to
the following release.
