# Protected Evidence Recovery — G0 experimental prerequisite

Related execution: IVOAI-199 / IVOAI-148 / IVOAI-192. This is one prerequisite of Phase B, not completion of those tasks or of the economic gate. Base source: `3be82befea6ed3875373afcb1bfaa450710310ac`. The adjacent [proposal](protected-evidence-recovery-proposal.md) is the earlier frozen source map and future design, not a list of delivered features.

## Delivered scope

The existing ArtifactStore supports a second opaque namespace, `evidence_<32 lowercase hex characters>`, emitted only when trusted host code sets `PutRequest.ProtectedRecovery`. Its zero value still emits `artifact_`. No tool accepts an artifact name, namespace, recovery policy, owner, scope, grant callback or generation. Existing ArtifactRef/ResultRef JSON and metadata schema/kinds remain unchanged. A custom ID generator must still return a valid legacy random-ID shape; it cannot choose the protected namespace itself.

Gateway issuance stores a canonical process-local request/ref binding after persistence and post-I/O authorization/generation checks. `RecoverBound` resolves that exact binding and delegates to the existing sealed `Recover` contract, including owner, scope, current grants, source generation, exact metadata, expiry and SHA verification. Primary and worker reuse may share the cached immutable retrieval but receive separate owner-specific ArtifactStore objects and refs. There is no mutable replay or new source scheduler.

Both existing Core readers recognize protected IDs before any legacy store read, independently of the creation flag. An absent binding/callback, a new Gateway or a restarted App fails closed; `read_range` follows the same rule and validates byte bounds. The implementation never reconstructs a lost seal or falls through to session-only LocalStore reads. Live bindings continue to use their captured grant policy after the creation flag is switched off; disabling creation is not a second authorization authority.

`IVOAI_EXPERIMENTAL_EVIDENCE_RECOVERY=1` is off by default. In the App it additionally requires the existing `IVOAI_EXPERIMENTAL_EVIDENCE_GATEWAY=1` code-prefetch path. Only the existing primary and read-only capability-profile workers in the same canonical worktree receive protected prefetch refs. Writers, other worktrees, direct prefetch without the Gateway flag and ordinary worker output keep their previous behavior.

A worker receives a host-created `externalmcp.Target.Local` behind its existing task-scoped bearer, `workers.Access`, grants and lifecycle. It exposes exactly `orchestration_artifact_read` and `orchestration_artifact_read_range`, whitelisted to the already-issued worker ref. It exposes no scheduler tools and creates no listener, source credentials, independent auth policy or durable capability store. Enabled MCP-name collisions and mismatched worker/worktree are errors. The original Gateway authorization callbacks remain decisive on every recovery.

Bindings are bounded to 64 unexpired refs per Gateway; admission fails before a new store write at capacity. No live capability is evicted to admit another. Expired bindings are pruned at subsequent protected admission. Existing cache entry/byte/flight bounds, ArtifactStore count/byte limits and TTL remain in force; there is no new dependency or database.

## Namespace, inventory and rollback audit

`workingcontext/model.go` centralizes ID validation. ArtifactRef validation, LocalStore read/path checks, quota inventory and GC use that validator. `local.go` keeps the ID-generator validator legacy-only and applies the host namespace choice after generation. Core reader schemas and argument validation accept both valid namespaces; only protected readers require the binding. No other production Go artifact-ID regex remains outside these deliberate validators.

The repository-wide non-Go scan also found `scripts/benchmark-rtk-generated.py:42`: its `artifact_` validator is deliberately unchanged. That harness consumes its existing unprotected output-view fixture; it is not a protected recovery consumer, and G0 does not change RTK or combine its benchmark rows with this pilot. The companion Python fixture keeps the same legacy contract. No TypeScript/JavaScript/Rust artifact-ID validator required a migration in this checkout.

The source-pinned rollback probe compiles actual Core readers and store code from base `3be82be` using already-present dependencies, without downloading or changing the checkout. It runs that executable against disposable objects created by the new store. The old full and range readers reject protected IDs; legacy read, write, inventory and GC continue working; protected payload bytes survive. Unknown IDs are skipped before parsing their otherwise unchanged metadata, avoiding poisoning old quota inventory.

**Rollback limitation:** old Core inventory and GC ignore protected directories, so they consume disk outside its counters and are not collected by that version. The new Core counts both namespaces under its existing 256 MiB global / 64 MiB per-session byte limits, 16 MiB per-object bound and 24 h default TTL (7 d maximum), in addition to the Gateway's 1 MiB payload / 64-binding limits. These are bounds while this Core runs; an old version can add its separate legacy allowance after rollback. Restore an understanding version to perform normal GC. Do not delete private evidence or weaken old validators to make rollback appear transparent. G0 does not persist protected refs into `Session.Workers[].ResultRefs`; existing output projection continues to issue legacy refs. Persisting protected ResultRefs into old strictly validated session metadata would require its own migration/version gate and is outside G0.

The namespace guarantee applies to newly marked refs. Historical unmarked Gateway stdout artifacts cannot retrospectively be distinguished from direct stdout, so their legacy access contract is unchanged. LocalStore remains trusted host storage; its direct Go methods are not an independent authorization service. Public Core reader routes enforce the Gateway boundary. This design neither promises uninterrupted recovery after loss of process-local bindings nor continuous remote authorization/freshness for external services.

## Evidence and limits

The adjacent `evidence/protected-evidence-recovery/validation.json` records exact commands, source/log digests, results and construction failures. Tests use labelled local repository / immutable snapshot fixtures and the actual MCP SDK Streamable HTTP transport through the existing Local target proxy and Access. They do not impersonate an institutional service, disable mandatory provider guards or perform native model inference. The rollback opt-in test explicitly skips without its separately built old Core executable; the script rejects skipped/missing named tests and exit failures. A normal full Go run's opt-in skips are not integration successes.

No live Memory/Context lookup adapter, institutional corpus generation, remote revocation epoch, cross-worktree/cross-process recovery, persistent seal, RTK/output-view replacement, native-client parity or economic improvement is delivered. Host grant checks protect retained already-authorized snapshots according to existing local policy; no constant generation is introduced for a live source. The next live-source pilot still needs explicit host snapshot identity or fresh upstream reads when no trustworthy generation exists. Context ingestion remains outside this slice; no claim of Context synchronization is made.

This branch is based on pre-PR47 Core source. Integration with adaptive primary must preserve its `guardTool` / `checkPrimaryTurn` wrappers when reconciling `addArtifactTools`; extraction here is not permission to remove turn/replay guards. The combined integration head requires its own full gates. This local prototype is not part of release 0.14 and is not release certification.
