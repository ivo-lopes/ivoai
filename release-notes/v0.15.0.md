`0bab9b3409a287917f73a5c0620a3758a4be5c36`, incorporating reviewed PR45
and its current-main composition. No tag, release asset, deployment or production

## Candidate scope

- **Native provider independence (IVOAI-195/192):** native Codex/Claude managed
  provider assembly excludes OpenCode discovery, quota probes, worker dispatch
  and fallback. Scoped catalogs and injected/stale plans are checked before
  effects. Native Codex-to-Claude frontend handoff and initial Claude planner
  remain explicitly unavailable rather than silently selecting a renderer.
- **Default setup:** ordinary client setup and updater candidate setup omit
  OpenCode. Explicit compatibility remains `ivoai setup --mode client --legacy-opencode`; the flag is refused for server setup. Explicit deprecated
  `ivoai opencode` and `ivoai auto` remain available. CI/release legacy assets and
  updater rollback participants remain: this is not global OpenCode removal.
- **Protected evidence G0 (IVOAI-199/148/192):** Gateway retrieval is wired into
  already-admitted code prefetch behind its default-OFF experimental flag.
  Protected Core/MCP exact recovery retains host bindings, exact owner, grants,
  source generation and separate namespace. Full primary readers also check active Core/receipt
  authority before and after recovery. Private worker readers expose only the
  two owner-bound protected read tools without a primary Store or scheduler.
  Creation remains opt-in through `IVOAI_EXPERIMENTAL_EVIDENCE_RECOVERY=1`;
  `IVOAI_EXPERIMENTAL_EVIDENCE_GATEWAY=1` separately controls Gateway retrieval.
  Lost bindings/restarts fail closed without legacy fallback. G1a Memory snapshot
  retention/classification SPI is included as **unwired**, not live Memory/Context
  integration or synchronized ingestion.
- **Adaptive primary pilot (IVOAI-192/193):**
  `IVOAI_EXPERIMENTAL_ADAPTIVE_PRIMARY` is **OFF by default**. Opt-in admits the
  first eligible literal user-message envelope of a fresh managed Codex session
  on the reviewed Linux amd64 0.162.1 client/companion pair. There is no prompt
  classifier and no VERSION-only restriction. Read-only capability can escalate
  through the existing Core DAG/approval flow; receipt consumption, stale-child
  refusal and no replay/failover policy remain authoritative. Synthetic official
  CLI metadata proofs do not establish general real-model quality or TUI parity.
- **Benchmark prerequisites (IVOAI-138/198):** matrix contracts, privacy-bounded
  observations, offline Gateway controls and PR55 concurrent-project preflight
  are source/test deliveries. PR55 does not execute concurrent clients, establish
  overlap or measure real workers. PR54 sampler calibration and PR56 are excluded.

## Migration and rollback

Native resume/recovery refuses retained OpenCode primary/task/worker/checkpoint
intent before discovery, receipt retirement or repository effects. It does not
rewrite or reroute saved work. Use explicit legacy continuation or create a new
native session with reviewed evidence. Existing component ownership, binaries,
client configuration, credentials, history, checkpoints and worktrees remain.
Default setup does not uninstall or repair an existing OpenCode installation.

For an isolated rollback, remove adaptive/Gateway/protected-creation opt-ins and
start a new session; stop owned disposable runs before replacing a Core. Restore
an independently verified matching previous Core/component set using the existing
update/rollback procedure. Do not delete retained history/checkpoints, reconstruct
lost protected bindings, reroute legacy tasks or replay uncertain mutations.
An old Core intentionally cannot recover protected namespace artifacts; their
quota/GC blind spot remains documented. Returning to old code restores its old
limitations and does not reverse unrelated state migrations.

Published v0.14.0 tag, assets, notes and historical negative evidence are unchanged.
