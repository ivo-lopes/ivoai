  already-admitted code prefetch behind its default-OFF experimental flag.

  `IVOAI_EXPERIMENTAL_ADAPTIVE_PRIMARY` is **OFF by default**. Opt-in admits the

## Migration and rollback

A managed invocation with `--ignore-user-config` must omit the flag rather than
change a personal config file or assume an alternative executor. Direct official
CLI and historical standalone pilots are outside this managed restriction;
this is a capability limit, not equivalent configuration-scope support.
The real canary cause remains UNKNOWN; the guard does not establish its cause.

Native resume/recovery refuses retained OpenCode primary/task/worker/checkpoint
intent before discovery, receipt retirement or repository effects. It does not
rewrite or reroute saved work. Use explicit legacy continuation or create a new
native session with reviewed evidence. Existing component ownership, binaries,
client configuration, credentials, history, checkpoints and worktrees remain.
Default setup does not uninstall or repair an existing OpenCode installation.

For an isolated rollback, remove adaptive/Gateway/protected-creation opt-ins and
start a new session; stop owned disposable runs before replacing a Core. Restore
an independently verified matching previous Core/component set using the existing
update/rollback procedure. Do not delete retained history/checkpoints, reconstruct
lost protected bindings, reroute legacy tasks or replay uncertain mutations.
An old Core intentionally cannot recover protected namespace artifacts; their
quota/GC blind spot remains documented. Returning to old code restores its old
limitations and does not reverse unrelated state migrations.

Published v0.14.0 tag, assets, notes and historical negative evidence are unchanged.
