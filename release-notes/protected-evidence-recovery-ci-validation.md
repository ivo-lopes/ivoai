## Required gate and provenance

CI `quality` and Release `verify` now invoke `scripts/test-protected-evidence-rollback.sh` unconditionally after full Go tests. Existing checkout steps have `fetch-depth: 0`, making the exact historical ancestor available. Release build/publish depends on `verify`; a failed rollback gate blocks that dependency. The gate has no condition, optional environment bypass, allowed failure, implicit Git fetch or module download. It does not turn the ordinary opt-in test's skip into integration success.

The historical revision remains exactly `3be82befea6ed3875373afcb1bfaa450710310ac`, checked as an ancestor with replacement objects disabled (`GIT_NO_REPLACE_OBJECTS=1`). `GIT_NO_LAZY_FETCH=1` also prevents implicit missing-object retrieval in a promisor repository on supporting Git versions; missing history or blobs fail rather than triggering fetch. CI uses a full checkout. Source is copied from that revision's blob objects into a private temporary tree, rejecting symlinks, gitlinks and unsafe paths. The proof directory records source revision/blob/SHA256 inventory and the separately injected test-helper digest. Historical `go.mod` and `go.sum` have explicit SHA256 pins, remain unchanged across compilation, and are identical to current main in this epoch.

Both legacy compilation and current test use `GOTOOLCHAIN=local`, `GOENV=off`, `GOWORK=off`, `GOFLAGS=-mod=readonly`, `GOPROXY=off`, `GOSUMDB=off`, `GONOPROXY=none`, `GONOSUMDB=none`, empty `GOPRIVATE`, and `GOVCS=*:off`. `go mod verify` checks both module caches before compilation; checksums verify both module manifests after the Go commands. The preceding full-Go workflow gate warms the existing checksummed dependency versions. Missing/altered cache or missing history fails explicitly, without an online fallback or a skipped proof. A future dependency change that makes the historical cache unavailable requires a reviewed cache preparation change; it is not permission to enable implicit downloads.

The old executable is built from the actual historical Core and its real ArtifactStore/read handlers, with only the labelled probe helper added. The current Go test executes it against disposable new-store artifacts, requires the named legacy test to pass, rejects legacy skips/failures, and checks protected bytes remain unchanged. The shell requires exit zero and validates JSON events: exactly one run/pass of `TestLiveProtectedArtifactsDoNotPoisonLegacyCoreRollback`, package success, the nested legacy contract marker, and no failed/skipped events. Missing, unrelated or duplicate proof events are rejected. Python parser fixtures are labelled as parser tests and do not count as a functional rollback run.
