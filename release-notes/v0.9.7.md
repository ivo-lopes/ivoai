# IVOAI v0.9.7 — Multi-server TUI and Connections

## Independent servers in the launcher

Open **ivoai → Connections → IVOAI Servers** to add, list and manage multiple
server profiles. Each alias has individual connection testing, enable/disable,
purpose/redundancy metadata editing, explicit re-enrollment and confirmed removal.
Enrollment codes use hidden input. Health is separate from enrollment; explicit
test observations expire after one minute rather than presenting stale success.

## No silent replacement or credential crossover

Add is create-only in both CLI and TUI. An existing alias produces a clear error;
use the explicit `re-enroll` operation to rotate its connection. Profile mutations
are serialized so competing enrollments fail busy instead of overwriting profiles.
Failed enrollment preserves other profiles and credentials.

Credentials remain in the private secret store, bound to stable server IDs.
Disable keeps the credential; re-enable does not require a new code while it is
valid. Remove affects only the selected profile and credential. Profile management
does not remove name-matching personal MCP entries from executor configuration.

## Compatibility and automation

The optional legacy `default` profile coexists with arbitrary aliases. Existing
v0.9.6 configuration and credentials need no schema migration or re-enrollment.
The legacy no-alias `connect server` retains its default reconnection behavior.

Automation gains the same `enable`, `disable`, `edit`, `re-enroll` and `remove`
operations under `ivoai connect server`; existing `disconnect server <alias>`
remains supported. Use `--code-stdin`, never a secret literal in shell history.
Buffered keyboard and piped menu input no longer stall or lose subsequent choices.

Use `ivoai update` through the normal checksum-verified updater. Existing snapshot,
rollback and reapply contracts are unchanged. Enable/disable and purpose changes
apply to new managed sessions, not an already-running session's source selection.

## Scope and limitations

This release delivers IVOAI-123. The v0.9.6 AUTO non-Git, pre-thread failure tracing,
legacy ai-memory ownership protection and multi-server diagnostics remain intact.
OpenCode remains the AUTO frontend; Claude Code remains an optional supported
executor. Aliases are stable; editing metadata does not rename an alias or identity.
No live health is inferred from enrollment. Real organization credentials are not
needed by the isolated multi-server/PTY smoke.

Prompt Gate and Economic Orchestration belong to v0.9.8 and are not delivered here.
