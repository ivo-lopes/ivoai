# IVOAI v0.12.0

This minor release consolidates PR #28's P1/P2 work and incorporates Graft as a
managed, scoped code-intelligence provider. Installation uses IVOAI's existing
component pipeline; no global npm installation, personal agent configuration,
upstream `init`, paid API or activation switch is required.

## Native code intelligence

- Reviewed Graft **0.21.1-ivoai.1**, upstream commit
  `fe30ead39d5e6f0c921018d364da2bdbc9d4b3ad`, private Node **26.11.1**.
- Library operations cover build, search, API signatures, callers, grouped literal
  search, maps, impact, freshness and private static visualization. The six native
  MCP operations and economic `code_inspect` share the authenticated capability
  gateway and session/tool grants.
- Runtime inspection chooses direct reads/literal search when sufficient and
  structural evidence for relations. Local aggregate cost history is bounded;
  unknown token/CPU/memory values remain unknown. Institutional source order is
  still Memory → Context. Compilers/tests remain authoritative for behavior.
- Private worktree snapshots, full-content invalidation, verified index sidecars,
  bounded result caching, one active structural process and eight admitted calls
  limit resource use. Queries have a 90-second timeout, a 32-KiB maximum result,
  256-MiB V8 heap and a monitored 512-MiB RSS threshold.
- Landlock plus seccomp blocks external network, child processes, filesystem
  escapes and unapproved writes. Indexing never runs repository scripts. Parser
  errors fail closed; missing structural evidence is not inferred from text.
- Native parser lifecycle cleanup bounds Tree-sitter memory. Reviewed Go import
  resolution handles package aliases and lexical shadowing without guessing
  globally. Static visualization escapes repository-controlled identifiers.

## Consolidated P1/P2 changes

Includes the merged hook preflight/recovery, typed telemetry/SSE, operational
OpenCode panel, model/reasoning presentation, automation profiles, shared CLI/TUI
services and logical-session continuity/recovery from PR #28. A real managed-client
smoke additionally exposed and fixed Codex companion resolution through a PATH
symlink: the registered distribution remains the ownership authority.

## Supply chain and compatibility

Linux amd64 and ARM64 builds use reviewed, lifecycle-disabled npm resolution and
explicit native compilation in an isolated build. ABI gates cap GLIBC at 2.35,
GLIBCXX at 3.4.30 and CXXABI at 1.3.13; the amd64 runtime is tested without AVX/AVX2.
Node requires the system libatomic runtime; IVOAI diagnoses it without installing
OS packages automatically. Runtime isolation requires a non-root process and
Landlock ABI 1 or newer; ABI 1/2 receive additional seccomp restrictions.

The managed archive contains source/patch provenance, dependency inventories,
per-file hashes and legal notices. Undici is pinned to reviewed 6.28.1. The unused
YAML CLI and its vulnerable argparse/sprintf-js chain are removed from runtime;
the preserved build lock retains that distinction. Only the 16 referenced WASM
grammars remain, with MIT/Apache-2.0/CC0 notices. Their prebuilt bytes are pinned;
upstream does not fully attest their resolved source revisions, so no independent
signature or source-reproducible WASM compilation claim is made.

## Validation and measured limits

See [the validation report](graft-native-validation.md) for exact workflow runs,
artifact checksums, tests and raw A/B measurements. One paired sample per scenario
is correctness and operational evidence, not a statistical savings guarantee.
Cold indexing has a real CPU/latency cost; short exact inspections can be cheaper
without a graph. Result bytes are not actual provider token counts.

Optional deep LLM enrichment and LSP subprocesses remain outside the admitted
runtime. The structural layer needs no API key. Claude paths use contracts and
fixtures in this release; **IVOAI-188 remains open for real Claude validation**
because the subscription is unavailable. A direct/native passthrough cannot
promise the orchestrator's worker prefetch or Skill Gate; managed sessions retain
those controls. No production deployment is performed.

## Update and recovery

Use the existing `ivoai update` and TUI update/rollback flows. Managed objects are
staged, integrity-checked and atomically promoted; previous objects remain available
for rollback. A runtime object change invalidates derived structural caches.
Personal skills, provider authentication and multi-server profiles preserve their
ownership boundaries. The index is disposable cache, not institutional memory.

This release does not migrate production databases. Before any ai-memory 1.x
migration, stop writes and validate a consistent data backup. Binary rollback does
not reverse a database migration.
