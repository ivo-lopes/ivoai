# IVOAI v0.9.5

## Authenticated external MCP connections

This hotfix adds client-owned authentication to the external HTTP MCP registry.
Existing entries without authentication continue working without re-registration.

- Bearer tokens and custom header values are stored in IVOAI's private `0600`
  secret store, bound to an opaque MCP identity and the exact registered endpoint.
  The public configuration contains authentication metadata, not credentials.
- CLI input uses stdin or a hidden terminal prompt. The External MCP Registry menu
  supports adding, configuring/replacing, removing authentication, adding headers,
  and testing initialization/tool discovery. List output reports sanitized status.
- Removing an external MCP also removes its associated credential. Rotation does
  not change its identity; changing an authenticated endpoint requires clearing
  authentication first.
- A session-local, authenticated loopback gateway keeps upstream credentials in
  the IVOAI process. Codex, Claude, and the controlled native OpenCode executor use
  ephemeral local references. Personal/global client configuration is unchanged.
- Full preauthorizes configured external MCP tool calls at the IVOAI gateway.
  Interactive displays a confirmation in the managed TUI before forwarding the
  call, avoiding the headless executor's `never` approval deadlock. Explicit native
  TUI fallback retains native approval handling. Interactive remains the default.
- Full does not bypass Skill Gate, Unix permissions, knowledge/source isolation,
  worker restrictions, or other IVOAI policies. Read-only advisory workers do not
  receive arbitrary external MCPs or their session capability.

The Plane Mindsite MCP was validated through real `ivoai auto` sessions using
`list_projects`, in both Full and Interactive modes. Its PAT endpoint requires
Bearer authentication **and** `X-Workspace-Slug`; a successful TLS connection or
Bearer alone is not sufficient. Memory/Context and requested/effective Codex model
and reasoning remained functional. Native OpenCode was tested with a credential-free
provider fixture; Claude remains an optional supported capability with renderer
contract coverage, without requiring operator login.

## Configure and rotate

Run these commands on the **client**, not on `ivoai-server`. The example variables
must be supplied securely; never put a literal credential in shell history.

```sh
ivoai connect mcp add plane-team https://mcp.example.com/http/api-key/mcp
printf '%s\n' "$PLANE_MCP_TOKEN" | ivoai connect mcp auth set plane-team --bearer-token-stdin
printf '%s\n' "$PLANE_WORKSPACE_SLUG" | ivoai connect mcp header set plane-team X-Workspace-Slug --value-stdin
ivoai connect mcp test plane-team
ivoai connect mcp list
ivoai config set opencode.permission_mode full
ivoai auto
```

Repeat `auth set` or `header set` to rotate. `auth remove <name>` removes the saved
Bearer and custom headers; `remove <name>` removes the registry entry as well.
Alternatively, open `ivoai` → External MCP Registry and use the hidden-input flow.
Authentication and permission changes take effect in the next session.

## Install and update

```sh
curl -fsSL https://raw.githubusercontent.com/ivo-lopes/ivoai/v0.9.5/install.sh | IVOAI_VERSION=v0.9.5 sh
```

Existing managed installations:

```sh
ivoai update --dry-run
ivoai update
ivoai version
ivoai connect mcp test plane-team
```

The official updater preserves compatible configuration and existing server
profiles. `ivoai update --rollback` restores its verified snapshot. Authentication
for external MCPs is new in this release: older binaries do not implement it.
Do not rotate credentials with an older version; reapply the current stable first.

## Scope and limitations

- This registry supports `none`, Bearer, and custom headers, not a new OAuth login
  implementation. Use the MCP service's supported PAT/header endpoint; OAuth-only
  services still require a separately supported authorization integration.
- Tool approvals mediate execution; they do not reinterpret arbitrary external
  tool annotations as safe or turn mutating tools into read-only operations.
- Upstream redirects are rejected to prevent credential forwarding to another
  endpoint. Request/response sizes, permission queues, and timeouts are bounded.
- Codex aliases containing dots are projected with underscores; collisions fail
  closed. Prefer letters, digits, underscores, and hyphens for portable aliases.
- This is a focused emergency hotfix, not a roadmap or documentation redesign.
  No remote production server upgrade is included.

See the matching [connection guide](https://github.com/ivo-lopes/ivoai/blob/v0.9.5/docs/connections.md).
